# Crew Emergency AI v0.2 — интеграция с Crew Heart Check

Локальный модуль: Qwen извлекает наблюдения, человек подтверждает, детерминированный код формирует учебный сценарий. Медицинские действия языковая модель не выбирает. Веса моделей в архив не включены, дообучение не выполнялось.

## Установка на Windows (PowerShell)

Открыть PowerShell в папке с server.py. Нужны Python 3.11+ (Windows x64) и установленный Ollama.

```powershell
python -m pip install vosk
ollama pull qwen3:4b
```

Скачать и распаковать обе модели Vosk при доступном интернете:

```powershell
New-Item -ItemType Directory -Force models | Out-Null
Invoke-WebRequest https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip -OutFile models\ru.zip
Expand-Archive models\ru.zip -DestinationPath models
Rename-Item models\vosk-model-small-ru-0.22 vosk-model-small-ru
Invoke-WebRequest https://alphacephei.com/vosk/models/vosk-model-small-en-us-0.15.zip -OutFile models\en.zip
Expand-Archive models\en.zip -DestinationPath models
```

Эти команды предназначены для первой установки, когда папок моделей ещё нет. Также есть повторно запускаемый download_vosk.ps1: он оставляет существующие папки нетронутыми. Если выполнение ps1 запрещено настройками Windows, используйте команды выше или скачайте архивы вручную с https://alphacephei.com/vosk/models .

Получится:

- models/vosk-model-small-ru/am/, conf/, graph/...
- models/vosk-model-small-en-us-0.15/am/, conf/, graph/...

Для русского также поддерживается исходное имя vosk-model-small-ru-0.22. Не должно быть лишнего уровня вложенности. Модели Vosk имеют собственные лицензии; указанные две модели опубликованы как Apache 2.0. При ошибках установки пришлите версию Python и полный вывод pip; зависимости не устанавливаются автоматически сервером.

## Запуск и проверка

```powershell
python server.py
```

При старте в фоне загружаются Vosk и выполняется реальный пробный запрос к Qwen. Пока загрузка идёт, health может показывать false. Сервер остаётся доступным.

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health | ConvertTo-Json -Depth 5
```

Пример здорового состояния (НЕ обещание текущего результата):

```json
{"server":"ok","stt":{"ru":true,"en":true},"llm":{"ready":true,"model":"qwen3:4b","warm":true},"clinical_protocol_enabled":false}
```

llm.ready = пробный запрос реально вернул ожидаемый JSON при запуске. Это не оценка медицинской точности и не гарантия следующего запроса. llm.warm = проверено присутствие модели в /api/ps. Для повторной стартовой проверки после исправления Ollama перезапустить сервер. stt.ru/en = соответствующая модель успешно загружена Vosk; наличие папки само по себе не считается готовностью.

Все обращения к модели используют keep_alive:-1; Ollama пытается держать её в памяти. Это занимает RAM/VRAM и не гарантирует отсутствие вытеснения. Чтобы освободить память вручную: ollama stop qwen3:4b.

## Интерфейс

- Если рядом с server.py есть crew-heart-check.html, он отдаётся по http://127.0.0.1:8765/ .
- Иначе / отдаёт демонстрационную страницу.
- Демонстрационная страница всегда доступна на http://127.0.0.1:8765/demo .
- Интерфейс и API имеют один origin: CORS не требуется. Не открывать HTML через file://.
- Эта версия обслуживает только указанные страницы и API. Дополнительные файлы CSS/JS/картинки отдельно не раздаются: интерфейс должен быть самодостаточным HTML либо сервер потребуется расширить. Внешние CDN надо исключить для полной автономности.

## Offline STT

POST /stt: сырые байты little-endian PCM16, один канал, 16000 Гц, от 1 сэмпла до 15 секунд (480000 байт). X-Lang: ru или en, Content-Type: application/octet-stream. WAV/WebM/Ogg не являются сырым PCM; frontend обязан декодировать, перевести в моно и ресэмплировать. Сервер не определяет частоту/каналы по raw-байтам; это часть контракта клиента.

Успех: {"text":"...","lang":"ru","ms":340}. ms — обработка Vosk, без загрузки модели, записи аудио и передачи. Тишина может дать пустой text; не отправлять пустую строку в /extract. Отсутствующая/не загруженная модель или Vosk: 503 {"error":"stt_unavailable"}. Неверный язык/нечётное число байт/пустой PCM: 400. Больше 15 секунд: 413. Аудио не сохраняется.

Для проверки готового WAV (PCM16/mono/16kHz, до 15 с) есть transcribe_wav.py:

```powershell
python transcribe_wav.py sample.wav --lang ru
```

После распознавания сначала показать человеку текст для проверки: ошибка STT в отрицании может изменить смысл. /stt не запускает /extract автоматически. Запись микрофона делает интерфейс Claude; demo не содержит кнопки записи.

## Извлечение фактов и скорость

Поля: responsive, normal_breathing, chest_pain, aed_ready, medic_present, bleeding, choking. /extract возвращает только найденные yes/no и цитаты; отсутствие поля означает unknown. Не считать отсутствие поля значением no. /confirm по-прежнему допускает ручное unknown.

В подсказке 3 примера в фиксированном порядке. Цитаты проверяются по исходному тексту без учёта регистра и восстанавливаются в исходном написании. Это не доказывает правильность интерпретации; подтверждение человеком обязательно.

ms в /extract — реальное wall-время локального извлечения, включая запрос к Ollama, обработку промпта, генерацию, проверку и возможное ожидание очереди, без записи в SQLite. Это не чистое GPU-время. Поле есть и при ручном fallback; статус manual_required не считать успешным ИИ-разбором.

CREW_MODEL переключает модель:

```powershell
$env:CREW_MODEL = 'qwen3:1.7b'
python server.py
```

## Сравнение моделей

Сначала скачать обе модели, затем остановить Python-сервер, оставив Ollama запущенным. Не вести параллельные диалоги при замерах.

```powershell
ollama pull qwen3:1.7b
python evaluate.py
python evaluate.py eval_extended.jsonl --compare --output benchmark_result.json
```

Первая команда evaluate проверяет исходные 20 примеров на CREW_MODEL (по умолчанию qwen3:4b). Сравнение прогоняет 30 примеров на qwen3:4b и qwen3:1.7b последовательно, записывает ms каждого примера, mean/p50/p95 и ошибки. Каждый прогон предваряется пробным запросом; время прогрева записывается отдельно. keep_alive:-1 может оставлять обе модели резидентными, если они помещаются; для чистого сравнения при ограниченной памяти используйте два отдельных запуска с ollama stop между ними:

```powershell
$env:CREW_MODEL = 'qwen3:4b'
python evaluate.py eval_extended.jsonl --output benchmark_4b.json
ollama stop qwen3:4b
$env:CREW_MODEL = 'qwen3:1.7b'
python evaluate.py eval_extended.jsonl --output benchmark_1_7b.json
ollama stop qwen3:1.7b
$env:CREW_MODEL = 'qwen3:4b'
```

Это разработческий набор, а не клиническая валидация. Ранее полученные пользователем 20/20 относятся к предыдущей подсказке из 6 примеров: после сокращения промпта и новых полей точность нужно измерить заново. Новые 10 примеров также являются открытыми разработческими тестами.

В среде подготовки нет Ollama, Qwen и моделей Vosk. Попытка сравнения записана в benchmark_environment.json: обе модели unavailable, время null, протестировано 0. Реальную точность и задержку НЕ заявляем. Выполнены 29 тестов кода/HTTP, включая подмену ответов модели и Vosk; реальное распознавание речи здесь не проверено.

```powershell
python -m unittest discover -v
```

## Сценарий, оборудование и журнал

Сохранены: явная среда миссии, ручная готовность AED/CMRS/изолированной поверхности, подтверждение фактов, уточнения, учебный сценарий для отсутствия реакции в микрогравитации, отметки выполнения, экспорт журнала. bleeding/choking извлекаются и подтверждаются, но лечебные ветки для них НЕ реализованы. Нельзя заявлять полноценную помощь при этих состояниях.

NASA используется для архитектуры поддержки, DGLRM/ESAM 2020 — для опубликованных особенностей микрогравитации, Красный Крест — для общих принципов. Полные документы и руководства конкретных аппаратов не включены. Источники и локальные резюме: sources.json. Клиническое исполнение выключено, инструкция модели всегда null. Учебные шаги задаются кодом scenario.py, не свободной генерацией.

Журнал crew_journal.sqlite3 хранится рядом с server.py (теперь независимо от текущей папки PowerShell). Старый журнал из другой рабочей папки автоматически не переносится. Не удаляйте его при обновлении. Сетевой отправки на Землю нет. Сервер слушает только loopback, без аккаунтов и шифрования; для демонстрации используйте синтетические данные.

## Проверка микрофона и состояния загрузки (обновление v0.2)

`/health` сохраняет stt.ru/en как boolean для совместимости и добавляет stt_status.ru/en:

- loading — модель найдена и ожидает/проходит загрузку;
- not_installed — папка модели не найдена;
- dependency_missing — папка есть, но библиотека Vosk не импортируется;
- error — Vosk не смог загрузить найденную модель;
- ready — модель успешно загружена.

В llm.status: loading / not_installed (Ollama вернул 404 на модель) / unavailable (Ollama недоступен) / error / ready. Прежние ready/model/warm сохранены. Обработчик значка в интерфейсе Claude должен использовать status; сервер не меняет сторонний HTML автоматически.

Проверять нужно на том компьютере, где запущены Python-сервер и модели, независимо от того, на каком устройстве открыт чат с Claude. Для другого ноутбука localhost относится к другому компьютеру; не пытайтесь открыть локальный сервер первого через localhost второго.

Установка поддержки микрофона (один раз при доступном интернете):

```powershell
python -m pip install sounddevice
```

Оставить server.py работающим в одном окне PowerShell. Во втором окне, в той же папке:

```powershell
python mic_check.py
```

Скрипт сначала проверяет готовность Vosk. Потом по очереди показывает 6 русских и 6 английских фраз. Нажмите Enter, произнесите полную фразу за 7 секунд, дождитесь распознанного текста. Отметьте y/n/? — сохранён ли смысл. Аудио не сохраняется и отправляется только локальному /stt. Результаты после каждой фразы пишутся в vosk_microphone_results.json, поэтому Ctrl+C не теряет завершённые записи.

При неудаче с микрофоном: python -m sounddevice покажет устройства, затем python mic_check.py --device 1 (подставить фактический номер входа). При отказе Windows проверьте разрешение микрофона для настольных приложений. Если 16000 Гц не поддерживается устройством, скрипт использует его штатную частоту и линейную интерполяцию в 16000; исходная частота записывается в отчёт. Это диагностический конвертер, качество ресэмплинга также может влиять на результат. WER измеряет различия слов, а не медицинскую правильность; особенно проверяйте отрицания вручную.

Сравнение Qwen требует только Ollama, не Python-сервер. Остановите server.py перед benchmark, затем запустите его снова для микрофонного теста. Поделиться с Claude можно двумя JSON: benchmark_result.json и vosk_microphone_results.json. Наличие результатов теста на одном ноутбуке не доказывает готовность моделей на другом.

## Интегрированная версия: серверные проверки и подтверждение

Этот архив объединяет интерфейс Claude с актуальным сервером, mic_check.py, расширенным health и подсказкой ambiguity-r1. Установить содержимое папки поверх рабочей версии. Не удалять models/, crew_journal.sqlite3 и свои JSON результатов. В поставку НЕ входят веса Vosk/Qwen или пользовательский журнал.

Новое:

- guards.py проверяет известные ошибки сразу после структурной проверки ответа модели. Проверяется цитата и её контекст в сообщении. Неподтверждённый результат удаляется из facts; guard_warnings содержит поле, исходную цитату, причину и value:unknown.
- Слова о дыхании без явного указания нормальности не дают normal_breathing:yes. «Не знаю», «не оценивали», сон и неподтверждённая готовность оборудования обрабатываются консервативно. Если важное наблюдение могло быть пропущено моделью, предупреждение требует проверки, но НЕ превращается автоматически в установленный факт.
- В локальном интерфейсе текст и STT больше не вызывают старый обработчик голосовых действий до подтверждения. Простое упоминание AED не отмечает его применение. Голос теперь вводит сведения; подтверждение и отметки выполнения — кнопками. На локальной странице нет автоматического перехода на облачное распознавание при недоступном Vosk.
- Исходный текст виден в карточке, есть кнопка исправления. Смена профиля/фазы/связи или редактирование блокирует устаревшее подтверждение.
- При микрогравитации ветка нормального дыхания больше не показывает земное положение на боку и соответствующую анимацию. Это ограничение прототипа, а НЕ готовая альтернативная процедура позиционирования. Остальные лечебные разделы интерфейса не прошли полной клинической проверки; явно обозначен учебный режим.
- Google Fonts исключены, Three.js уже был встроен Claude. Статическая проверка не обнаружила внешних script/link-зависимостей, необходимых для запуска. Внешние источники по ссылкам по-прежнему требуют сети. Озвучивание зависит от доступных локальных голосов ОС.

Проверки: 49 Python-тестов, node test_ui_contract.js и синтаксис JS прошли. Полноценный браузерный/визуальный прогон в среде подготовки не выполнен: Chromium не смог запуститься из-за ограничений среды. Qwen и Vosk реально здесь не запускались.

В guard_replay_results.json воспроизведены ТОЛЬКО 5 ошибочных ответов из присланного журнала прошлой подсказки. Защита исправляет 4 из этих 5; оставшийся пропуск сведений о дыхании остаётся неизвестным и требует уточнения. Это не новый прогон модели и не оценка всех 50 примеров. Ответы прежде успешно пройденных случаев в журнале отсутствовали, поэтому регрессии на них этим воспроизведением не проверены.

Новый evaluate.py показывает:

- raw_passed / raw_failed — структурно корректные ответы модели ДО guards;
- passed / failed — ответы ПОСЛЕ guards;
- guard_interventions — количество предупреждений;
- critical_metrics.raw/guarded — ошибки полей responsive/normal_breathing: no_to_yes, unknown_to_yes, no_to_unknown. Это счётчики разработческих случаев, не доказательство клинической безопасности.

Проверить на ноутбуке, остановив Python-сервер и оставив Ollama:

```powershell
$env:CREW_MODEL = 'qwen3:4b'
python evaluate.py eval_extended.jsonl --output evaluation_guarded_4b.json
python evaluate.py eval_control.jsonl --output evaluation_guarded_control_4b.json
```

После исправлений прежний контрольный набор также стал набором регрессии. Для последующей оценки обобщения нужен ещё один новый набор, не используемый при настройке.

Ограничения защиты: конечные шаблоны не распознают любой контекст, могут избыточно оставлять сведения неизвестными, не исправляют гарантированно потерянные Vosk слова и не доказывают истинность сообщения. Пользователь может вручную изменить предложение; это сохраняется как подтверждение человеком. Формулировку «ИИ не способен уменьшить срочность» использовать нельзя.
